1 Dual-Persona Architecture & User Experience

Seamless separation between Organizer Control Hub and Devotee/Community Member Portal

👑

Admin & Organizer Control Hub

Route: /events (for Committee & Admins)

  • ✓ Festival Master Creation: Multi-step wizard to setup festival schedules, banner images, ticket classes, and venues.
  • ✓ Sub-Activity Modules: Configure Pooja Sevas, Meal menus, Cultural concerts, and Competitions.
  • ✓ Unified Registration Ledger: Search, filter by category/status, check-in attendees, and view payment receipts.
  • ✓ Logistics & Kitchen: Real-time Annadanam food preparation progress and volunteer duty allocations.
  • ✓ Fundraising & Sponsors: Sponsor pledges, community donations, budget vs. actual expenses, and auction bids.
🪔

Devotee & Member Portal

Route: /events (for Community Residents)

  • ✓ Live Hero Banner & Details: Interactive countdown and "Details" modal for complete event prospectus.
  • ✓ Sacred Pooja Booking: Select date & time slots with family members, Gotram, and Sankalpam.
  • ✓ Meal / Annadanam Tokens: Reserve lunch/dinner dining hall plate passes with instant token generation.
  • ✓ Digital QR Gate Passes: Segregated pass views (Active, Cancelled, Expired, Closed) with gate scanner QR codes.
  • ✓ Self-Service Management: Devotees can update attending counts or cancel passes with automatic slot restoration.

4 Interactive System Sequence Flows

Lifecycle interactions between Client, Spring Boot Service Layer, and Database

🔄 Flow 1: Devotee Pooja Slot Booking with Automatic Capacity Decrement

sequenceDiagram autonumber actor Devotee as Devotee / User participant UI as EventMemberView participant Controller as EventBookingRegistrationController participant Service as EventBookingRegistrationServiceImpl participant SlotRepo as PoojaSevaRepository participant DB as event_booking_registrations Devotee->>UI: Select Pooja Seva & click "Book Seva Slot" UI->>UI: Select Date, Time Slot, Gotram & Attending Family UI->>Controller: POST /api/events/registrations Controller->>Service: createRegistration(reg, user, communityId) Service->>Service: Validate non-duplicate active booking Service->>SlotRepo: Decrement slot capacity by devoteeCount SlotRepo-->>SlotRepo: Update pooja_seva_day_time_slots (slots = slots - N) Service->>Service: Generate unique regCode (e.g. POOJA-4921) Service->>DB: Save registration with status='CONFIRMED' DB-->>Service: Saved Entity Service-->>Controller: Return EventBookingRegistration Controller-->>UI: 201 Created (with QR Code payload) UI->>Devotee: Display Valid Digital Gate Pass

🛡️ Flow 2: QR Gate Pass Scanning & Real-time Verification

sequenceDiagram autonumber actor GateStaff as Security / Gate Volunteer participant Scanner as Gate Scanner Device participant API as /api/events/registrations/{id} participant DB as event_booking_registrations GateStaff->>Scanner: Scan Devotee's QR Code Pass Scanner->>API: GET /api/events/registrations/{id} or verify regCode API->>DB: Fetch registration & parent event status alt Event or Registration is CANCELLED API-->>Scanner: 🚫 CANCELLED / VOID Pass (Red Banner) Scanner->>GateStaff: Deny Gate Admission else Event Date has Expired API-->>Scanner: ⏰ EXPIRED Pass (Amber Alert) Scanner->>GateStaff: Concluded Event Notice else Pass is ACTIVE & VALID API->>DB: UPDATE checked_in=true, checked_in_at=NOW() API-->>Scanner: ✅ VALID GATE PASS (Green Confirmation) Scanner->>GateStaff: Admit Devotee & Family end

♻️ Flow 3: Pass Cancellation with Automatic Slot Capacity Restoration

sequenceDiagram autonumber actor Devotee as Devotee / Admin participant UI as ManagePassModal / DetailsModal participant API as POST /api/events/registrations/{id}/cancel participant Service as EventBookingRegistrationServiceImpl participant SlotRepo as PoojaSevaRepo / MealRepo / CompRepo participant DB as event_booking_registrations Devotee->>UI: Click "Cancel Registration" & enter Reason UI->>API: POST /api/events/registrations/{id}/cancel?reason=... API->>Service: cancelRegistration(id, reason, user) Service->>DB: Set status='CANCELLED', cancellationReason=reason, cancelledAt=NOW() Service->>SlotRepo: incrementActivitySlots(registration) Note over Service,SlotRepo: Automatically restores booked seats/plates to Pooja or Meal SlotRepo-->>SlotRepo: Update slots = slots + devoteeCount DB-->>Service: Saved Entity Service-->>API: 204 No Content API-->>UI: Success Notification UI->>Devotee: Pass marked CANCELLED with watermark, slots freed for others
